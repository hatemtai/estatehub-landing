The parts that take months.

Search, deals, verification and money are the slow features of any marketplace. Here they are built, connected to the API and documented.

  1. Map-first search that keeps its state in the URL

    Buyers browse price pins on a live map, narrow down with a filter panel, or describe what they want in a sentence. Every search can be bookmarked, shared or restored with the back button.

    • Leaflet with OpenStreetMap tiles, so no map API key
    • Radius search from a dropped pin or the visitor's location
    • AI search turns a sentence into ordinary filters

  2. Deals tracked from reservation to handover

    A buyer reserves a property, uploads payment proof and follows the deal stage by stage. Administrators work through a checklist for each transaction and complete each stage.

    • Purchase and lease flows with their own stages
    • Stages and checklist items come from the server
    • Checklist templates are editable in admin settings

  3. Identity and business verification

    Customers complete a six-step identity check. Sellers apply through a guided business verification wizard. Administrators review both from a single queue.

    • Document and selfie upload with previews
    • Status shown on the profile and the seller application

  4. Finance for both sides of the deal

    Sellers see what each property earns after platform fees and request payouts. Administrators verify payments, record manual ones and transfer approved payouts in batches.

    • Commission and reservation rules set in admin
    • Payments export to CSV

  5. Real-time messaging and notifications

    Buyers and sellers chat over WebSockets, with typing indicators, read receipts and image attachments. A floating chat dock follows the visitor from page to page.

    • Notification centre for all three audiences
    • Per-category notification preferences

  6. Rebrand it without a rebuild

    The platform name, logo and brand colours load from the API. Change them in the admin console and the public site and both portals follow.

    • Storage, email, bank transfer and social sign-in set up in admin
    • Saved secrets are write-only

Before you buy.

The practical details of running and customising EstateHub.

What do I need to run it?

Node.js 20.9 or newer, pnpm, and the URL of an EstateHub REST API. Copy the example environment file, set the API URL, then run the install and dev commands. The API URL is the only required variable.

Where can I deploy it?

Anywhere Next.js runs. Import the repository into Vercel or a similar platform, or build it and serve it from your own Node server behind a reverse proxy such as Nginx or Caddy.

Can I rebrand it without editing code?

Yes. The platform name, logo, favicon and brand colours are set in the admin console and load from the API, so a rebrand needs no rebuild. For deeper changes, the design tokens live in one stylesheet.

Do the maps need a paid API key?

No. The listing map uses Leaflet with OpenStreetMap tiles, which need no key.

Is dark mode available everywhere?

The seller portal and admin console switch between light and dark. The public site and customer account are light, and the design system documentation lists the steps to opt them in.

How are social sign-in, storage and email configured?

From the admin console under Settings, Integrations. Credentials are not environment variables, and saved secrets are write-only: the console shows whether a value is set, never the value itself.

Which AI providers does AI search support?

OpenAI, Anthropic and Gemini. An administrator picks the provider and model and switches the feature on. When it is off, the ordinary search and filters work as usual.
